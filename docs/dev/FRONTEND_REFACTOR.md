# Dashboard 前端重構計畫

> 建立 2026-10-21。分支 `feature/frontend-redesign`。
> 範圍：`src/main/resources/assets/dashboard/` 的架構重構＋視覺精修（方案 A）＋頁面分工調整。
> 依據：anthropics/skills 的 `frontend-design` skill，以及 2026-10-21 與 Fu 的三輪討論。

## 已定案的決策

| 項目 | 決策 |
|---|---|
| 視覺方向 | **方案 A：保留原風格（米色底、藍主題、卡片版面）系統化精修**。全新視覺（冷灰底＋跑道藍色帶＋DIN 數字字型）經 mockup 否決：字太細、圖形化的本週執行看不懂、不喜歡配色 |
| 字型 | 維持系統字型，不引入 CDN 或字型檔 |
| 架構 | 改用 **ES modules**，依職責拆檔；不引入建置工具 |
| 週規則 | 月曆格**週日開頭**；所有「本週」統計用**課表週＝週一到週日**（週末長距離與週日比賽屬同一循環），標題寫明日期範圍 |
| 頁面分工 | 見下表 |

| 頁面 | 回答的問題 | 內容 |
|---|---|---|
| 總覽 | 我現在實力如何、整體狀況如何 | VDOT、個人最佳成績、近期跑量、心率區間、訓練負荷摘要、AI 分析 |
| 今日 | 今天練什麼、身體準備好了嗎 | 今日／明日課表、準備度、HRV、睡眠、本課表週執行狀況、最近訓練 |
| 行事曆 | 每一週練得怎樣 | 月曆；點某天展開該課表週（一到日）的課表、實際與執行狀態 |
| 趨勢 | 長期怎麼變化 | 訓練負荷＋身體狀況（合併原兩頁），共用時間範圍切換 |
| 訓練紀錄 | 某一場跑得如何 | 不變 |
| 設定 | — | 維持右上齒輪進入，不佔導覽列 |

舊網址 `#/load`、`#/wellness` 轉到 `#/trends`，書籤不失效。

## 階段

每階段完成即 commit；push 時機由 Fu 決定。

### 階段 1：ES modules 拆檔（畫面不變）
- [x] `app.py` 註冊 `.js` 的 MIME 為 `text/javascript`（Windows 登錄檔可能把 `.js` 標成 `text/plain`，module 會被瀏覽器拒絕）
- [x] `app.js` 依職責拆到 `js/`：`core/`（dom、api、format、state、tooltip、info-popover、router）、`views/`（today、overview、calendar、sessions、load、wellness、settings）、`main.js`
- [x] `charts.js`、`theme.js`、`coach.js` 改為 module；`coach.js` 改用 `core/dom.js`、`core/api.js`，移除重複的 `$`／`h`／`clear`／`api`
- [x] `mock-data.js` 維持 classic script（`document.write` 在 module 執行前完成，`window.MOCK_API` 照常可用）
- **驗證**：7 頁 × 桌機／桌機深色／平板／手機 共 28 個畫面，加上 5 個互動情境（切 range、點月曆日、選場次、ⓘ 浮層、切主題）與 2 個 `?mock=1` 畫面，與改動前版本逐一截圖比對：PNG 位元組完全相同、console 無新錯誤；851 項單元測試通過
- ✅ 2026-10-21 完成
