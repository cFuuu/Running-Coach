# Dashboard 前端重構計畫

> 建立 2026-10-21。分支 `feature/frontend-redesign`。
> 範圍：`src/main/resources/assets/dashboard/` 的架構重構＋視覺精修（方案 A）＋頁面分工調整。
> 依據：anthropics/skills 的 `frontend-design` skill，以及 2026-10-21 與 Fu 的三輪討論。

## 已定案的決策

| 項目 | 決策 |
|---|---|
| 視覺方向 | **方案 A：保留原風格（米色底、藍主題、卡片版面）系統化精修**。全新視覺（冷灰底＋跑道藍色帶＋DIN 數字字型）經 mockup 否決：字太細、圖形化的本週執行看不懂、不喜歡配色 |
| 字型 | 維持系統字型，不引入 CDN 或字型檔 |
| 架構 | 改用 **ES modules**，依職責拆檔；不引入建置工具 |
| 週規則 | 月曆格**週日開頭**；所有「本週」統計用**課表週＝週一到週日**（週末長距離與週日比賽屬同一循環），標題寫明日期範圍 |
| 頁面分工 | 見下表 |

| 頁面 | 回答的問題 | 內容 |
|---|---|---|
| 總覽 | 我現在實力如何、整體狀況如何 | VDOT、個人最佳成績、近期跑量、心率區間、訓練負荷摘要、AI 分析 |
| 今日 | 今天練什麼、身體準備好了嗎 | 今日／明日課表、準備度、HRV、睡眠、本課表週執行狀況、最近訓練 |
| 行事曆 | 每一週練得怎樣 | 月曆；點某天展開該課表週（一到日）的課表、實際與執行狀態 |
| 趨勢 | 長期怎麼變化 | 訓練負荷＋身體狀況（合併原兩頁），共用時間範圍切換 |
| 訓練紀錄 | 某一場跑得如何 | 不變 |
| 設定 | — | 維持右上齒輪進入，不佔導覽列 |

舊網址 `#/load`、`#/wellness` 轉到 `#/trends`，書籤不失效。

## 階段

每階段完成即 commit；push 時機由 Fu 決定。

### 階段 1：ES modules 拆檔（畫面不變）
- [x] `app.py` 註冊 `.js` 的 MIME 為 `text/javascript`（Windows 登錄檔可能把 `.js` 標成 `text/plain`，module 會被瀏覽器拒絕）
- [x] `app.js` 依職責拆到 `js/`：`core/`（dom、api、format、state、tooltip、info-popover、router）、`views/`（today、overview、calendar、sessions、load、wellness、settings）、`main.js`
- [x] `charts.js`、`theme.js`、`coach.js` 改為 module；`coach.js` 改用 `core/dom.js`、`core/api.js`，移除重複的 `$`／`h`／`clear`／`api`
- [x] `mock-data.js` 維持 classic script（`document.write` 在 module 執行前完成，`window.MOCK_API` 照常可用）
- **驗證**：7 頁 × 桌機／桌機深色／平板／手機 共 28 個畫面，加上 5 個互動情境（切 range、點月曆日、選場次、ⓘ 浮層、切主題）與 2 個 `?mock=1` 畫面，與改動前版本逐一截圖比對：PNG 位元組完全相同、console 無新錯誤；851 項單元測試通過
- ✅ 2026-10-21 完成

### 階段 2：修正兩個既有 bug

- [x] `loadTodayKpi`、`loadRecentSessions` 自行附加 `athlete_id`，`api()` 又附加一次 → 移除呼叫端那份
- [x] 順手統一：`athlete_id` 附加邏輯抽成 `core/api.js` 的 `withAthlete()`，`coach.js` 改用同一份
- **驗證**：Playwright 模擬台灣 07:00，`todayISO()` 回 10-21（舊寫法回 10-20）；meta 載入後重觸發今日頁載入，19 個 API 請求無重複 `athlete_id`；回歸比對 35 情境文字與 DOM 全同（2 個僅像素差，為截圖時機抖動）；851 項測試通過
- ✅ 2026-10-21 完成

### 階段 6：總覽與今日合併為首頁、趨勢頁依類別重組（2026-10-21 追加）

**數據分類**（全站一致，首頁放「現在的值」、趨勢放「走勢」）：

| 類別 | 回答的問題 | 數據 |
|---|---|---|
| ① 課表執行 | 今天練什麼、這週練得如何 | 今日／明日課表、課表週摘要與執行表、最近訓練＋對應課表 |
| ② 訓練量 | 跑了多少 | 本週跑量、每週跑量（強度堆疊）、跨場距離 |
| ③ 強度分布 | 強度配得對不對 | 心率區間分布、本週 Zone 2、跨場平均心率 |
| ④ 訓練負荷 | 負荷有沒有過量 | ATL／CTL／TSB、Garmin 急性負荷、Garmin 負荷比指數、恢復時間 |
| ⑤ 恢復與身體 | 身體準備好了嗎 | 準備度（規則引擎）、HRV、Garmin HRV 狀態、靜止心率、睡眠、Garmin 訓練準備度、壓力、血氧、呼吸率、步數 |
| ⑥ 能力與成績 | 我現在多強 | VDOT、個人最佳成績、跨場平均配速、有氧 TE |

盤點時發現的重複：TSB 出現 4 處、HRV 3 處、每週跑量 2 處——合併後各只出現一次目前值＋一次走勢。

**決策**
- 總覽＋今日合併為「首頁」，固定看現在、不吃時間範圍；導覽改為 首頁、行事曆、趨勢、訓練紀錄（舊網址 `#/today`、`#/overview` 轉址）
- 首頁 6 個區塊：今天（課表＋準備度，半欄）、訓練負荷（卡片＋ⓘ，半欄）、身體狀況（卡片）、本課表週、能力與成績（VDOT 卡＋最佳成績卡）、最近訓練；以區塊為單位自訂順序與顯隱
- 頂列右上：同步資料、分析近況、系統設定三顆「圖示＋文字」按鈕（手機只留圖示）；日夜切換移出頂列，只留在設定頁
- 趨勢依類別排列，預設順序 負荷 → 身體 → 強度 → 能力 → 訓練量；電腦一列 2 張圖、手機 1 張；摘要列與資料品質移到趨勢頂端；刪除與強度堆疊圖重複的「週跑量」長條圖；類別可排序、圖表可隱藏
- 自訂設定沿用 `rc-dashboard-settings`（theme.js），不另開 key；身體狀況既有的排序／顯隱機制推廣成共用元件

**步驟**

- [x] 6b 共用自訂元件 `js/core/customize.js`（排序／顯隱面板＋偏好存讀），身體狀況改用它；實測沿用既有 `wellness` 設定
